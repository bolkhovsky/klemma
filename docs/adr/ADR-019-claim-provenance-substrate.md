# ADR-019 Claim Provenance Substrate

**Status**: Accepted
**Date**: 2026-08-14
**Plan**: `docs/plans/2026-08-13-claim-provenance-gap.md`
**Predecessor**: ADR-018 (citation integrity verification)

## Context

Сплошной аудит статьи gningi (12.08.2026, 30 утверждений, 14 источников) дал 11 расхождений,
и ни одно не было галлюцинацией: источники существуют, citekey верны. Ломался слой **между**
источником и текстом — потеря квалификаторов, потеря адресата нормы, верное утверждение под
неверной ссылкой, наследование дефекта между собственными работами.

`check-citations` (ADR-018) существовал, но под ним не было субстрата (замер на 13.08.2026):

- полный текст сохранён у 9 из 443 источников (2 %);
- `verbatim = 1` — у 0 из 2450 фрагментов;
- `draft/chapter_1.md`: 15 якорей, 0 verified, 15 unverifiable;
- `papers/gningi/paper_draft_v2.md`: 0 якорей — статья на нумерованных ссылках `[n]`,
  движок искал только `[@citekey]`;
- `process` возвращал `completed` при упавших эмбеддингах (12/12 фрагментов без вектора).

Одновременно принят продуктовый пивот: SaaS заморожен, Klemma — личный CLI-инструмент для
сборки диссертации; выполнение перенесено на сервер fram (эмбеддинги — Ollama/bge-m3 локально).

## Decision

Шесть решений, реализованных стеком PR (миграция v16):

### 1. Полный текст — первоклассный актив
Sidecar `.klemma/pdfs/<citekey>.md` пишется **сразу после** `extract_pages()`, до вызова AI —
текст сохраняется даже при отказе экстракции. `sources.pdf_text_length` заполняется.
`SidecarDoc` (`literature/sidecar.py`) даёт постраничные char-оффсеты, выводя их из маркеров
`<!-- Page N -->` при чтении; отдельной таблицы оффсетов нет намеренно — вторая правда
дрейфовала бы при каждой перезаписи sidecar.

### 2. Провенанс фрагмента: span + локатор + честный verbatim
`fragments` получает `char_start`/`char_end` (span в канонический текст sidecar) и
`source_locator` («п. 3.4», «табл. 2», «с. 12»; эвристика advisory-only, `literature/locator.py`).
`klemma repair --steps sidecar,verbatim,embeddings` пересчитывает `verbatim` у **всех**
фрагментов источника, включая даунгрейд true→false — честность важнее «never downgrade»
(прежний `backfill-verbatim` остаётся deprecated-алиасом). Правило работы: фрагмент годится,
чтобы найти место в источнике; цитировать можно только по полному тексту.

### 3. Режим нумерованных ссылок
`check-citations` понимает `[5]` / `[5, 12]` / `[5, п. 3.4]`: библиография разбирается с
сохранением номеров, `reference_matcher.build_ref_map()` строит карту номер→citekey
(DOI точно → титул fuzzy + год → авторы+год). Каждая нумерованная цитата получает синтетический
якорь `kind="reference"` — клейм попадает в отчёт даже без числового/цитатного якоря.
Несопоставленный номер и анафора («Там же») — находки soft_warn, не тихие пропуски.

### 4. Claims — реестр, а не заметка
Таблица `claims` (UNIQUE(manuscript_path, claim_hash, anchor_key)): аудит — состояние,
живущее между сессиями. `claim_hash` — sha256 нормализованного предложения + citekey +
ref_number; правка предложения = staleness by design. Регистрируются и безъякорные клеймы
(verdict NULL → `unchecked`). `klemma claims status --gate` — ворота перед подачей: exit 1
при stale/unchecked/вердикте ≥ fail-on; пустой реестр тоже проваливает gate
(«не проверялось» ≠ «чисто»).

### 5. Статус degraded
`ProcessingStatus.DEGRADED` + `sources.degraded_steps` (JSON). Отказ эмбеддингов/sidecar
больше не глотается: источник помечается degraded с перечнем шагов, `klemma status --degraded`
показывает очередь дообработки, `repair` возвращает в completed. `repair --scan` находит
исторические тихие отказы.

### 6. Граница хранилищ (контр-ADR-014, осознанно)
Весь субстрат пишется в **legacy** проектную `.klemma/data/klemma.db` — именно там живёт
рабочая диссертационная база. Three-tier (`project.db`/`library.db`) не расширяется:
в `library.db` — только существующий dual-write `verbatim`. Консолидация three-tier отложена
вместе с SaaS.

## Consequences

- `check-citations` получает tier-1 evidence (`search_complete=True`) для источников после
  `repair`; papers/ впервые попадают в контур верификации.
- Обратный поиск (`klemma find-source "<утверждение>"`) закрывает класс «верно, но не тот
  источник» — ранжирует кандидатов по эмбеддингам фрагментов и источников.
- Spans валидны только для поколения sidecar, против которого посчитаны: любой пересчёт
  sidecar обязан перезапускать verbatim/span-шаг (repair делает это в одном вызове).
- Изменение sentence-boundary логики массово состарит claims — это честно и дёшево
  при `--incremental`.
- Выполнение klemma — только на fram (fram-run-only зафиксирован в KLEMMA.md диссертации);
  машинные пути в трекнутом конфиге диссертации корректны по этому решению.
