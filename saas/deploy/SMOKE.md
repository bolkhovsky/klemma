# Смоук-чеклист (C4)

Предполётная проверка перед каждым показом лиду — самая дешёвая страховка во
всём плане безопасности. На этапе 2 (выделение коммерческого репозитория)
этот же чеклист становится критерием переключения домена на новый портал.

Два блока: автоматический (curl, без входа в аккаунт) и ручной (через
браузер, с реальным логином). Прогонять оба перед показом; автоматический —
можно и просто время от времени.

## Автоматический блок — пять хостов, с проверкой тела

Код ответа один не защищает: `litresearch.ru` однажды отдавал 200 с чужим
телом (RFM вместо своего API — коллизия алиаса `api` в docker-сети, см. фикс
30.07.2026). Смотреть **и** статус, **и** содержимое.

```bash
curl -s https://klemma.bolkhovsky.ru/health          # {"status":"ok",...,"service":"klemma-api"}
curl -s https://stt.bolkhovsky.ru/v1/health           # {"status":"ok","worker":{"running":true,...}}
curl -s https://litresearch.ru/api/health             # {"status":"ok",...,"service":"klemma-api"}
curl -s https://miz.bolkhovsky.ru/ | grep -o '<title>[^<]*'   # <title>MIZ ...
curl -s https://rfm.bolkhovsky.ru/ | grep -o '<title>[^<]*'   # <title>RFM-админка
```

`stt.bolkhovsky.ru/v1/health` отдаёт `200` даже при `degraded` — смотреть
именно `"worker":{"running":true}`, а не только код ответа.

Дополнительно (главный тест недели безопасности, из плана A3):

```bash
ssh klemma 'sudo ss -tlnp | grep 18080'   # ровно ОДИН слушатель, на 172.18.0.1
```

## Ручной блок — через браузер, klemma.bolkhovsky.ru

1. **Логин** — реальным аккаунтом, не тестовым
2. **Список встреч** — карточки отрисовались, даты не пустые
3. **Карточка встречи** — открывается, протокол читается
4. **`/ask`** — вопрос по содержимому встречи, ответ пришёл и по делу
5. **Аналитика** — раздел открывается, графики/цифры не нулевые без причины
6. **Запись с телефона до `ready`** — записать короткое совещание, дождаться
   статуса `ready` в приложении
7. **Открытие протокола по `portal_url`** — ссылка, которую отдал воркер,
   ведёт на карточку именно этой записи (`/m/:sourceId`)

Пункт 6–7 — единственная проверка, которая касается ВСЕГО пути целиком:
телефон → fram (ASR + извлечение) → ingest → портал → ссылка обратно на
телефон. Дешевле не бывает, но требует физической записи, поэтому не
автоматизирован.

## Если что-то не прошло

- Автоматический блок красный → сначала `docker ps` на VPS (все контейнеры
  `healthy`?), потом `journalctl` соответствующего сервиса
- Ручной блок красный, автоматический зелёный → баг в конкретном экране, не
  в инфраструктуре — смотреть логи `klemma-mi-portal`
- `stt.bolkhovsky.ru` зелёный, но `/m/:sourceId` не открывается → см.
  рунбук `klemma-stt/deploy/fram/README.md`, раздел про `NO_PROXY`/туннель
